# Go の特徴・設計思想メモ

学習メモ。Go の設計思想を「シンプルな仕組みの組み合わせで済ませる」という
ケン・トンプソン的ミニマリズムの観点から整理したもの。

## 用語（前提）

| 用語 | 意味 |
|------|------|
| コンパイル | 実行前に、コードの間違いをチェックして実行可能な形に変換する作業 |
| コンパイル時 | コンパイルが行われているタイミング（まだプログラムは動いていない） |
| 実行時 | プログラムが実際に動いている最中のタイミング |
| 型（かた） | データの種類（int＝整数、string＝文字列、Dog＝独自に作った種類 など） |
| シグネチャ | メソッドの「名前・引数の型・返り値の型」という設計情報のみ。処理内容は含まない |

---

## ① ポインタ演算ができない安全性

**たとえ話：マンションの部屋番号**

住所（ポインタ）を持っている状態:

```go
p := &x   // 「x さんの部屋番号」を知っている状態
```

C という古い言語では、この番号に勝手に数字を足して「隣の部屋、そのまた隣…」と
好き放題移動できた（ポインタ演算）。管理外の部屋に踏み込んで壊す事故が多発した。

Go では「部屋番号を知る」ことはできても、「番号に足し算して移動する」ことは
言語のルールとして禁止されている。

```go
p := &x
p++    // ← コンパイルエラー。実行する前に弾かれる
```

**「安全性」の意味**：危険な操作をそもそも書けないようにして、事故が起きる前に防ぐ。

## ② 多値の返り値（Multiple Return Values）

**たとえ話：自動販売機**

普通、関数は結果を 1 つだけ返すのが基本（C# もそう）。
Go の関数は自動販売機のように一度に 2 つ以上返せる。

```go
func Divide(a, b int) (int, error) {
    // int＝計算結果、error＝エラー情報 を「同時に」返す
    if b == 0 {
        return 0, errors.New("0では割れません")
    }
    return a / b, nil   // nil は「エラーはなかった」
}
```

ジュース（結果）とお釣り（付加情報）を同時に出すように、
「計算結果」と「エラー情報」をセットで返す。これが③の土台。

## ③ エラー処理が「容易」ということ

**たとえ話：宅配便の受け取り**

C# の「例外（exception）」は、配達員がトラブル時にいきなり大声で叫んで、
離れた場所の別の人（catch 文）に処理を丸投げするイメージ。
叫び声がどこに届くかコードを読むだけでは分かりにくい。

```csharp
try {
    var result = Divide(10, 0);  // ここで例外が「投げられる」
} catch (Exception e) {          // 遠くで誰かが「受け取る」
    // ...
}
```

Go はこれをしない。配達員はトラブルの有無にかかわらず、必ず
「荷物」と「トラブルメモ」をセットで手渡す（②の多値を使う）。

```go
result, err := Divide(10, 0)
// result が荷物、err がトラブルメモ
if err != nil {
    log.Fatal(err)
}
```

**「容易」の意味は 2 つ**：

1. 叫び声（例外）がどこかへ飛んでいく見えない移動がない。上から下に読めば分かる。
2. トラブルメモ（err）がその場に必ず出現する。無視するには `_` と書いて
   「受け取ったが読まない」と明示する必要があり、うっかり見逃しにくい。

## ④ インターフェースの埋め込み

前提：インターフェース＝シグネチャ（メソッドの設計情報）だけを集めた契約書。

**たとえ話：アルバイトの募集要項**

```go
type Reader interface {
    Read(p []byte) (n int, err error)   // 「読み込みができること」
}
type Writer interface {
    Write(p []byte) (n int, err error)  // 「書き込みができること」
}
```

「読み込みスキル必須」の求人票と「書き込みスキル必須」の求人票が別々にある状態。

```go
type ReadWriter interface {
    Reader   // 埋め込み＝「Reader の条件もそのまま含める」
    Writer   // 埋め込み＝「Writer の条件もそのまま含める」
}
```

2 枚の求人票の条件を 1 枚に合体させる行為。
この `ReadWriter` を満たすには、struct 側が `Read` と `Write` の
両方のシグネチャを実装している必要がある。

---

## 4 つに共通する Go の姿勢

| # | やっていること |
|---|----------------|
| ① | 危険な操作（ポインタ演算）を言語仕様から消す |
| ② | 「複数の情報をまとめて返す」というシンプルな仕組みを用意する |
| ③ | ②を使って、エラーを特別扱いせず普通の値として扱う |
| ④ | 契約書（interface）を小さい部品の組み合わせで作れるようにする |

通底しているのは、**特別な例外ルールを増やすのではなく、シンプルな仕組みの
組み合わせで済ませる**という考え方。これがケン・トンプソン的なミニマリズム。
